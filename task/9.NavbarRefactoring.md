# Задача 9 — Перенос анимации позиции навбара в `useNavbarPosition`

## Контекст и цель

Сейчас позиция `.nav` анимируется **двумя разными сценами в разных слоях**:

| Слой       | Файл                    | Что твинит                                                             |
| ---------- | ----------------------- | ---------------------------------------------------------------------- |
| Дискретная | `useNavbarAnimation`    | `gsap.to(nav, { x, overwrite: 'auto' })` на `state:change` (не scroll) |
| Scrub      | `useNavbarScrubTrigger` | `tl.fromTo(nav, {x:0} → navX)` внутри scrubbed-таймлайна спейсера      |

Два владельца одной DOM-ноды конфликтуют: дискретный `gsap.to` с `overwrite:
'auto'` убивает scrub-твин из живой scrubbed-таймлайна, а `retargetScrub` на
tablet пересоздаёт его. Гонка `overwrite → kill → rebuild → refresh` после
ручного toggle на tablet может оставить scrub-твил отвязанным. Так как при
`source === 'scroll'` дискретная сцена делает ранний `return`, на `progress ≈ 0`
навбар **нечем** вытянуть в `fullscreen` ничем, кроме scrub-твина → «не
автораскрывается при прокрутке к началу страницы».

Цель (одобрено): **передать владение анимацией позиции `.nav` в навбар** —
отдельный хук-сцена `useNavbarPosition` (вариант B: хук, не логика в JSX),
оставив один владелец ноды, убрав кросс-сценовую гонку `overwrite`/rebuild
и устранив класс бага структурно.

## Решения пользователя

1. **Scrub остаётся через `onScrollProgress`** — навбар сам строит scrubbed-твин,
   подписываясь на низкоуровневый канал прогресса (ScrollTrigger живёт в провайдере/странице).
2. **Делается хук** (вариант B) — `useNavbarPosition`, вызывается из навбара.
3. **Регистрация спейсера остаётся** в `HomePage` через `registerScrollTrigger`
   (контракт со страницами не меняется).

## Что меняется по файлам

### 1. НОВЫЙ `hooks/useNavbarPosition.ts` — единственный владелец `.nav`

- Владеет `navRef` (получает через опции) и **всей** анимацией позиции:
  - **scrubbed-твин** (paused): `gsap.fromTo(nav, {x:0} → {x: getHomeEndState(),
ease:'none', paused:true, immediateRender:false})`. Подпитан
    `useNavbarScrollProgress`: `tween.progress(progress)`.
  - **дискретная анимация**: `useNavbarEvent('state:change')`, для
    `source !== 'scroll'` — `gsap.to(nav, {x: getNavTransform(state).navX,
duration:0.6, ease:'power2.inOut', overwrite:'auto'})`.
- Регистрирует «ретаргет» через контекст — при смене ручного tablet-выбора
  (useNavbarToggle меняет `preferredRef`). Регистрация — `contextSafe`-обёрнутый `buildScrub`.
- Сборка scrub-твина живёт в `useGSAP` (layout-эффект), чтобы подписка на
  `state:change` была зарегистрирована до того, как `useNavbarState` опубликует
  начальное состояние (сохранён прежний порядок: layout-эффект раньше
  passive-эффекта).
- Один владелец ноды → дискретная анимация больше не убивает scrub-твин:
  paused-твин не «активен», `overwrite:'auto'` его не трогает.

### 2. `hooks/useNavbarScrubTrigger.ts` — сокращение

- Удалить собственный nav-твин (`buildNavTween`), `navTransform()` в твине.
- Удалить `retargetScrubRef`, возвращаемый `retargetScrub` (и его `useCallback` фасад).
- Опции без `navRef`.
- Пустой scrubbed-таймлайн остаётся (носитель `ScrollTrigger`): `onUpdate`
  с `applyState` на progress 0/1, `spacer:enter/leave`, канал
  `scrollListenersRef`, видимость toggle. Позицию навбара больше НЕ ведёт.

### 3. `hooks/useNavbarAnimation.ts` — удалить

- Логика дискретной анимации переехала в `useNavbarPosition`. Файл удаляется.

### 4. `hooks/useNavbarToggle.ts`

- Опция `retargetScrub` убирается из options; обработчик читает
  `const { retargetScrub } = useNavbar();` (фасад над рефом провайдера).
- `preferredRef`/депсы без изменения поведения.

### 5. `hooks/useNavbarLayout.ts`

- Убрать параметр `refs` (`NavbarLayoutRefs` удаляется).
- Убрать вызов `useNavbarAnimation`.
- `useNavbarScrubTrigger` без `navRef`; `useNavbarToggle` без `retargetScrub`.
- `NavbarLayout` возвращает прежний API (`applyState`, `registerScrollTrigger`,
  `scrollListenersRef`, `getHomeEndState`, `currentState`).

### 6. `core/navbarContext.ts`

- В `NavbarAPI` добавить через контекст:
  - `getHomeEndState: () => NavState` — для построения scrub-твина.
  - `retargetScrub: () => void` — фасад: `() => retargetScrubRef.current?.()`.
  - `registerRetargetScrub: (fn: (() => void)|null) => () => void` —
    регистрация ретаргета из `useNavbarPosition` (cleanup возвращает
    отмену). По образцу `onScrollProgress`/`onToggleVisibility`.

### 7. `NavigationBarProvider.tsx`

- Убрать `navRef` (владение переехало в `NavigationBar`).
- Завести `retargetScrubRef = useRef<(() => void) | null>(null)`;
  `retargetScrub`/`registerRetargetScrub` — стабильные `useCallback`.
- В `NavbarAPI`: `getHomeEndState` (берёт из layout, стабилен по bp),
  `retargetScrub`, `registerRetargetScrub`.
- `<NavigationBar isSlim={isSlim} hasToggle={hasToggle} />` (без `navRef`).
- deps `api`-`useMemo`: добавить новые поля (стабильные).

### 8. `NavigationBar.tsx`

- `const navRef = useRef<HTMLElement>(null); useNavbarPosition({ navRef });`.
- Убрать проп `navRef` из `NavigationBarProps`. Разметка остаётся.

### 9. `index.ts`

- Большой экспорт `NavTransform` (без toggleX), `SLIM_WIDTH`, etc. автоматически;
  удалить экспорт `NavbarLayoutRefs`.

## Что НЕ меняется

- Контракт страниц `registerScrollTrigger(trigger)`.
- `onScrollProgress` / `onToggleVisibility` / `useNavbarEvent` — каналы те же.
- `useNavbarState`, `preferredRef`, pin-логика (`isManualMobileState`) — без изменений.
- `getContentOffset`, `<main>`, window-модель навбара (`navX`).
- `ToggleButton` — своя нода и свой ref.
- breakpoints/`getNavTransform`/`homeEndStateFor` — без изменений.

## Критерии приёмки / ручная проверка

- `npm run lint`, `npm run build`, `npm run format`.
- **Баг**: Tablet `/home` — скролл в конец спейсера → ручной toggle standard↔slim
  → скролл вверх через спейсер к началу → навбар ВСЁ РАВНО автораскрывается в
  fullscreen.
- Mobile `/home`: scrub fullscreen→invisible; ручной pin ☰/← «держится» до верха
  (поведение сохранено).
- Tablet `/home`: скролл к началу принудительно даёт fullscreen; при обратном
  скролле вниз возвращается последний ручной выбор (slim/standard).
- `/other` mobile/tablet: поведение не изменилось (invisible/slim → ручной toggle).
- Desktop: кнопки нет, `/home` fullscreen↔standard.
- Смена роута/breakpoint: scrub-твин перестраивается корректно, нет «залипания» позиции.
- Performance: нет setState в scrub-слушателях; scrub-позиция — `tween.progress` на
  композиторе (без reflow).
