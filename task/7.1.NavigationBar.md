Этот архитектурный паттерн можно назвать «Децентрализованное управление анимацией через Фабрику Таймлайнов в Контексте» (Context-Driven Animation Factory / Controlled Component Animation).
Его суть: Компонент-Владелец (в вашем случае <NavigationBar />) полностью инкапсулирует внутри себя DOM-ноды и саму суть анимации (какие свойства меняются, с какой скоростью и эффектами). Но контроль над тем, когда, как и от чего эта анимация запускается (скролл, клик, событие), он делегирует наружу через React Context с помощью функций-оберток.

## Mind Flow (Ментальная карта логики) для обучения нейросети

Чтобы другая нейросеть (или разработчик) мгновенно поняла паттерн, скопируйте ей следующий Mind Flow / Сценарий работы:

[ Навбар (Глобальный) ] ──(Регистрирует в Context)──> [ API управления анимацией ]
│
┌─────────────────────────────────────────────────────────┴───────────────────────────────────────────────────────┐
▼ ▼
[ Страница А (Монтирование) ] [ Кнопка / Событие в UI ]
│ │
├─► Извлекает `registerScrollTrigger(element)` ├─► Извлекает `playManualAnimation('open')`
├─► Создает временный ScrollTrigger внутри useEffect ├─► Временно отключает текущий ScrollTrigger (.disable(false))
│ ├─► Запускает независимый твин/таймлайн для ручного открытия
[ Страница А (Скролл) ] │
│ [ Умный Скролл-Прослушиватель ]
└─► Scrub плавно двигает плейхед таймлайна навбара │
└─► Пользователь скроллит > 150px после клика?
[ Страница А (Размонтирование) ] │
│ └──► ДА: Возвращаем управление скроллу (.enable())
└─► Вызывается `trigger.kill()`. ScrollTrigger уничтожен. └──► НЕТ: Навбар остается открытым
Навбар готов для других страниц в чистом виде.

## Промпт-описание паттерна для нейросети (Шаблон для копирования)

Если вам нужно поставить задачу другой нейросети, отправьте ей этот структурированный текст:

Патент: Context-Driven Animation Factory (Фабрика анимаций через React Context).
Проблема, которую решаем: Компонент А (глобальный элемент UI, например, NavigationBar) должен анимироваться от скролла на Странице Б через gsap.ScrollTrigger с жесткой привязкой (scrub: true). При этом другие дочерние компоненты (например, кнопки на странице) должны иметь возможность принудительно запускать/перезапускать эту же анимацию вручную вне зависимости от скролла. При уходе со Страницы Б скролл-триггер должен бесследно уничтожаться (kill()), чтобы не ломать логику на других страницах.
Ключевые правила паттерна:

1.  Единственная ответственность (Solid): Компонент А хранит DOM-ссылки на свои элементы и знает как их анимировать, но не знает когда. Он не инициализирует ScrollTrigger внутри себя при старте.
2.  Абстракция через Контекст: Компонент А оборачивает приложение в Provider и прокидывает наружу методы управления:

- registerScrollTrigger(targetElement) — функция, которая принимает элемент со страницы, на лету создает для него ScrollTrigger и привязывает к нему таймлайн Компонента А.
  - playManualAnimation(direction) — функция для императивного запуска анимации (клики, таймеры) с временной заморозкой скролл-триггера.

3.  Жизненный цикл на вызывающей стороне: Страница Б в своем useEffect вызывает registerScrollTrigger(ref). В секции clean-up (return () => ...) страница сама уничтожает (.kill()) этот триггер при размонтировании.
4.  Разрешение конфликтов (Mutex принцип): Ручной вызов анимации через playManualAnimation обязан вызывать метод ScrollTrigger.disable(false), чтобы «скруббер» скролла не перехватывал управление элементами во время ручной анимации и не создавал визуальных рывков. После ручного действия контроль скролла восстанавливается через .enable().

## Главные преимущества паттерна для AI-генерации кода:

- No Memory Leaks (Нет утечек памяти): Так как за очистку триггера отвечает та страница, которая его запросила, GSAP-анимации не будут накапливаться в оперативной памяти при переходах между роутами react-router.
- Zero UI Jerking (Отсутствие прыжков UI): Использование флага disable(false) позволяет замораживать влияние скролла без сброса инлайновых CSS-стилей (элементы не прыгают в начальную точку при клике).
- Компонентная независимость: Навбар остается полностью изолированным модулем. Вы можете перенести его в другой проект, и он будет работать везде, где его попросят привязаться к скроллу.
