# Синхронная перецеливка scrub-а навбара при TOGGLE внизу /home

## Проблема

На `/home` (tablet) после `REACH_BOTTOM` (`mode = homeEndState`, прогресс
`p≈1`) клик по toggle меняет `homeEndState`. Контент плавно анимирует
`--nav-content-offset` за `0.45s / power3.inOut` (из `snapshot.transition`),
а навбар «прыгал» **мгновенно**: `shouldAnimateDiscrete` = `false`
(`isHome && !manual`), и `buildScrub` делал `scrubTween.progress(prevProgress)`
без анимации. Действие `RETARGET_SCRUB` в коде не обрабатывается
(`GsapProvider` ловит только `SCROLL_TO_END`), поэтому перецеливка шла криво.

## Решение

В `useNavPosition.buildScrub` при перецеливке (уже есть scrub-твин)
проигрывать плавную анимацию навбара к новой геометрии с теми же
`snapshot.transition.duration/ease`, что и контент, и лишь по завершении
пересобрать scrub. Отдельный обработчик `RETARGET_SCRUB` не нужен —
`useGSAP` и так перезапускает `buildScrub` при смене `homeEndState`.

## Изменения

- `src/components/Layout/nav/NavigationBar/useNavPosition.ts`
  - `buildScrub`: при `hadScrub` — `gsap.to(nav, {x: endX*prevProgress,
duration: snapshot.transition.duration, ease: snapshot.transition.ease,
overwrite:'auto', onComplete → пересборка scrub через fromTo(…paused…)
и progress(getSpacerScrollProgress())})`.
  - первая сборка (без предыдущего твина) — без анимации, как раньше.
- `src/components/Layout/nav/NavigationBar/useNavPosition.test.tsx`
  - переписан тест пересборки scrub-а: проверяет плавный `gsap.to` с
    `x = endX*prevProgress` и `duration/ease === snapshot.transition`,
    затем по `onComplete` — пересборку scrub-а.
  - добавлен тест: TOGGLE внизу `/home` → nav-перецеливка использует
    `snapshot.transition.duration/ease` (синхронно с контентом).

## Проверка

- `npm run test` / `lint` / `build` — зелёные (140 тестов).
- Ручная: `/home` tablet → доскроллить до конца → TOGGLE → навбар и контент
  плывут к новой границе синхронно (~0.45s); скролл после работает.

## Вне scope

- RC2: `endX` scrub-твина не пересобирается при ресайзе внутри breakpoint
  (в deps `useNavPosition` нет viewport) — отдельная задача.
- `docs/.../README.md` утверждает, что `GsapProvider` исполняет `RETARGET_SCRUB`;
  фактически обработка живёт в `buildScrub` (документацию можно уточнить).
