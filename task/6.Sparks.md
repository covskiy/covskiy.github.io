# Задача: Рефакторинг и чистая реализация анимации искр (Particle System)

В проекте (React 19 + GSAP 3 + Canvas 2D) необходимо реализовать эффект вылета искр внутри силуэтов букв SVG-логотипа.
Есть компонента LogoText.tsx которая выводит текст в svg, где есть набор букв оформленных через path. Нужно внутри силуэтов букв вписать анимацию искр -> анимацию частиц, которые в два пучка вылетают из правой части и летят влево. Каждый пучок представляет не разовый выброс, а группу с небольшим промежутком между стартом каждой искры(распределены по временному сектору). Во время вылета второго пучка, частицам первого(если их время жизни еще осталось) добавляется скорость полета. Искра летит не по прямой линии, чтобы повторить витиеватое поведение реальных искр. Искра имеет время жизни, от которого зависит её яркость и величина/цвет дымного хвоста, который она оставляет. Твоя задача — написать модульный, архитектурно грамотный код.

## 1. Архитектура (Строгое разделение модулей)

Тебе нужно создать/обновить файлы, разделив логику на 3 независимых слоя. **Не смешивай их!**

### Слой 1: Конфигурация (`sparks.config.ts`)

Все «магические числа», визуальные параметры и профили должны лежать здесь. Никакого хардкода в логике частиц.

- Цвета (ядро, хвост, дым).
- Множители яркости для разных пучков (burst1, burst2).
- Физические параметры (скорости, трение, ветер, амплитуда синуса).
- Профили для разных экранов (mobile/tablet/desktop) — выбираются по `window.innerWidth`.
- Тайминги (позиции burst1 и burst2 на локальном таймлайне, длительности, интервалы).

### Слой 2: Particle System (`sparks.system.ts` или класс)

Чистая логика, **не знающая** ни про React, ни про GSAP, ни про DOM.

- Управление массивом частиц (`sparks[]`).
- Метод `emit(x, y, burstType)`: создание частицы с рандомизацией (jitter).
- Метод `update(dt)`: обновление физики (ветер, трение, синусоида по Y, старение).
- Метод `draw(ctx)`: 3-слойная отрисовка (Дымный halo -> Кометный хвост -> Яркое ядро). Учет времени жизни для затухания альфы и размера.
- Метод `boostAll(factor)`: резкое увеличение горизонтальной скорости для всех живых частиц.
- Метод `clear()`: очистка массива.

### Слой 3: Canvas & Оркестрация (`useSparkCanvas.ts` + интеграция в `LogoText.tsx`)

Связующее звено с React и GSAP.

- **Canvas Hook:** Инициализация `<canvas>`, синхронизация DPR (Device Pixel Ratio), ResizeObserver.
- **Path2D Clip:** Сборка единого `Path2D` из DOM-элементов путей букв (`#morphPath-*`) через `addPath` (чтобы получить union контуров, а не intersection). Применение клипа с учетом масштабирования viewBox.
- **Render Loop:** Использование `gsap.ticker` (или `requestAnimationFrame`) для вызова `system.update(dt)` и `system.draw(ctx)`. Цикл должен сам останавливаться, когда нет живых частиц, и чиститься при unmount.
- **GSAP Оркестрация:** В существующем `LogoText.tsx` (или через хук) добавить в `localTimeline` твины эмиссии.
  - Эмиссия должна быть не мгновенной, а растянутой во времени (staggered): твин меняет `progress` от 0 до 1, а в `onUpdate` мы эмитим частицы, если их запланированное время наступило.
  - На позиции `burst2` добавить вызов `system.boostAll()`.

## 2. Визуальное и физическое поведение (Суть эффекта)

- **Траектория:** Искры вылетают из правой части канваса и летят влево. Полет не линейный: добавь легкий случайный наклон и синусоидальное колебание по Y (имитация витиеватости реальных искр).
- **Два пучка (Bursts):**
  - `burst1`: базовый вылет.
  - `burst2`: вылет, который также дает «пинок» (`boostAll`) всем искрам из первого пучка, которые еще не погасли.
- **Жизненный цикл:** У каждой искры есть `lifetime`. От оставшегося времени жизни зависит: яркость ядра (альфа), длина и прозрачность кометного хвоста (история позиций в кольцевом буфере).
- **Клиппинг:** Искры должны быть видны **строго внутри** контуров букв (через `ctx.clip()` с собранным `Path2D`).

## 3. Интеграция в существующий проект

- Компоненты `LogoText`, `SplashPage` и их таймлайны (`localTimeline`, `masterTimeline`) **уже существуют**. Не пересоздавай их.
- Найди в `LogoText` место, где строится `localTimeline`, и аккуратно внедри туда твины эмиссии искр.
- Эмиссия должна подчиняться мастер-таймлайну (при `pause()` мастера новые искры не летят, но те, что уже в воздухе, должны спокойно догореть в своем render-loop).

## 4. Важные правила (Anti-Patterns)

- **Никаких утечек памяти:** При unmount компонента обязательно удаляй listener из `gsap.ticker`, очищай массив частиц и отменяй RAF(если был выбрал метод requestAnimationFrame).
- **Никакого motion blur через `clearRect` с альфой:** Очищай канвас полностью (`clearRect(0,0,w,h)`) каждый кадр, хвосты рисуй явно через историю позиций частицы.
- **Оптимизация (Culling):** Перед отрисовкой проверяй, находится ли искра в bounding box букв. Если нет — пропускай `arc()`, но продолжай обновлять её физику (она может залететь обратно).
- **Конфигурируемость:** Если нужно подобрать идеальный визуал, я должен иметь возможность изменить только цифры в `sparks.config.ts`, не лазя в логику физики или отрисовки.

Приступай к реализации. Начни с анализа текущих файлов `LogoText.tsx` и `timelines.ts`, чтобы понять, как лучше всего интегрировать оркестрацию. Затем создай конфиг, затем чистую систему частиц, и в конце — хук для канваса и интеграцию.
