# Фаза 2 — ToggleButton: viewport-fixed (fixed-сиблинг) + владение нодой

## Контекст и цель

На mobile кнопка «прилипает» к левому верхнему углу экрана через GSAP-противофазу
(`toggleX = -navX`): дискретно в `useNavbarAnimation` и внутри scrubbed-таймлайна
`/home` (`tl.to(toggleRef, {x}, 0)`). Причина — `position: fixed` не работает у
потомка трансформированного `.nav` (transform создаёт containing block).

Цель: **полностью удалить `toggleX` и противофазу**. Mobile-кнопка становится
настоящим `position: fixed` элементом **сиблингом** навбара (вне трансформированного
`.nav`); tablet-кнопка остаётся внутри `.nav` и «едет» с его краем. Заодно нода
кнопки целиком переходит во владение `ToggleButton` (провайдер перестаёт держать
`toggleRef`), а scrub-`toggleX` — самое хрупкое место — исчезает само.

## Что удаляется (чистая экономия)

| Сейчас                                                                 | После                                           |
| ---------------------------------------------------------------------- | ----------------------------------------------- |
| `toggleX` в `NavTransform`/`getNavTransform`                           | поле удалено, `getNavTransform` → только `navX` |
| дискретный mobile `toggleX` (useNavbarAnimation)                       | ветка удалена, анимация — только `nav.x`        |
| scrub `toggleX` в `tl.to(toggleRef,…)` (useNavbarScrubTrigger)         | удалён полностью                                |
| `toggleRef` у провайдера/layout/animation/scrub                        | реф только в `ToggleButton`                     |
| mobile `.nav { overflow: visible }` + `.navInner { overflow: hidden }` | `.nav { overflow: hidden }` на всех bp          |

## Изменения по файлам

### 1. `core/navbarStates.ts`

- `NavTransform` → `{ navX: number }`; `getNavTransform(state, viewport)` без `toggleX`.
  Параметр `bp` после удаления toggleX не нужен — убрать из сигнатуры и обновить
  всех вызовов, включая scrub и лог регистрации.

### 2. `components/ToggleButton.tsx` + `ToggleButton.module.css`

- Собственный `const ref = useRef<HTMLButtonElement>(null)`.
- Пропсы: `isSlim`, `hasToggle` (рендер). Breakpoint-режим — внутри через
  `useBreakpoint()` (без ре-публикации в шину).
- CSS: база `.toggleBtn` + модификаторы позиции:
  - `.toggleBtn--fixed` (mobile): `position: fixed; top:20px; left:20px`
  - `.toggleBtn--absolute` (tablet): `position: absolute; top:20px; right:20px`
- Подписка видимости: `useNavbarToggleVisibility((v) =>
gsap.set(ref.current, { autoAlpha: v ? 1 : 0, pointerEvents: v ? 'auto' : 'none' }))`.
- `onClick` → `events.emit('toggle:request', {})` (без изменений).
- Подписок на `state:change` для позиции больше нет (их нечего анимировать).

### 3. `NavigationBar.tsx` — placement по breakpoint

```tsx
<nav ref={navRef}>
  …логотип, <NavList …/>…
  {hasToggle && !isMobile && <ToggleButton isSlim={isSlim} hasToggle />}
</nav>
{hasToggle && isMobile && <ToggleButton isSlim={isSlim} hasToggle />}
```

- `isMobile` из `useBreakpoint()`; проп `toggleRef` из `NavigationBarProps` убирается.

### 4. `NavigationBarProvider.tsx`

- Убрать `toggleRef` и из `<NavigationBar>`, и из `useNavbarLayout` refs.
- Добавить `toggleVisibilityListenersRef: RefObject<Set<(visible: boolean) => void>>`
  (по образцу `scrollListenersRef`); чистка в cleanup.
- В `NavbarAPI`: `onToggleVisibility(listener) => () => void`.

### 5. `core/navbarContext.ts`

- В `NavbarAPI` добавить `onToggleVisibility`; хук `useNavbarToggleVisibility(listener)`
  по образцу `useNavbarScrollProgress`.

### 6. `hooks/useNavbarAnimation.ts`

- Опции без `toggleRef`; mobile-ветка кнопки удалена; твиним только `nav.x`.

### 7. `hooks/useNavbarScrubTrigger.ts`

- Опции без `toggleRef`; вместо него `toggleVisibilityListenersRef`.
- Удалить `tl.to(toggleRef, {x: …}, 0)` (scrub-противофаза).
- `setToggleVisibility(visible)` → `listeners.forEach(l => l(visible))`; правило
  (`progress >= 0.9999 || manualState`) остаётся в `onUpdate`.

### 8. `hooks/useNavbarLayout.ts`

- `NavbarLayoutRefs` без `toggleRef`; проброс `toggleVisibilityListenersRef` в scrub.

### 9. `index.ts`

- Экспорты `NavTransform` (без toggleX) — автоматически; новых публичных имён нет.

## Что НЕ меняется

- Шина: `toggle:request` (фаза 1) остаётся.
- State/route/breakpoint, `preferredRef`, pin-логика scrub (`isManualMobileState`
  остаётся — она про видимость и пин, не про позицию).
- `getContentOffset`, `<main>`, window-модель навбара (`navX`).

## Критерии приёмки / ручная проверка

- `npm run lint`, `npm run build`, `npm run format`.
- Mobile `/home`: scrub fullscreen→invisible — кнопка фиксирована в левом верхнем
  углу, в полёте скрыта, на `progress ≈ 1` видна `☰`; ручной pin `☰/←` — плавно
  (0.6s), без «дергания» от позиции.
- Mobile `/other`: `invisible ↔ fullscreen`, кнопка fixed.
- Tablet `/home` и `/other`: кнопка в правом верхнем углу навбара, «едет» с краем
  при slim↔standard.
- Desktop: кнопка не рендерится.
- Смена роута `/home → /other`: видимость сбрасывается, нет «залипшей» скрытой
  кнопки (cleanup канала).
- Смена breakpoint mobile↔tablet: кнопка «перепрыгивает» слева (fixed) направо
  (absolute) без потери подписки на видимость.
- Performance: нет setState в scrub-слушателях (видимость — только gsap.set).

- Убирает самую хрупкую связность фазы 2 (scrub-`toggleX`, спаянный с `navX`
