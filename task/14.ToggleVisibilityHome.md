# Задача 14 (ver2) — ToggleButton на /home: видимость в scrub-зоне и ручной override

ver2 фиксирует решения review v1 (см. §0.5 «Отличия от v1»): тест-харнес H3
(final-state-assert) + максимальная аннотация, эмиссия B1 (явный bool),
`lastProgressRef` в хуке видимости, расширение README §3/§6.

На `/home` позиция навбара управляется scrub-анимацией (ScrollTrigger + gsapBus),
поэтому кнопка toggle там должна быть скрыта — за двумя исключениями: «спейсер
пройден» (кнопка возвращается) и «навбар открыт вручную» (кнопка видна во время
обратного скролла до самого верха). Задача: перенести это правило в машину
состояний (ручной override, переживающий границу `REACH_BOTTOM`) и управлять
видимостью кнопки на 60fps через gsapBus.

### 0.5 Отличия от v1 (для чистого сеанса)

- **Фаза 7 переписана:** харнес H3 (final-state-assert) вместо «как preferredAfter».
  Дефолт `expectManualOverride` — strict-keep (ассерт `final === значение_до_шага`),
  а не «unchanged = undefined». Это убирает расхождение «8 существующих шагов
  возвращают non-undefined» — с H3 resolved-final они не падают.
- **Эмиссия зафиксирована как B1** (D13): `REACH_BOTTOM` else-ветка → `false`
  (не `undefined`), route/bp и `REACH_TOP` → всегда `false`, TOGGLE mobile → `true`.
  No-op и `INTRO_COMPLETE` → `undefined` — `toEqual({state, actions:[]})` в
  граничных it-блоках не протекает.
- **`useToggleVisibility`** дополнен `lastProgressRef` (D16) — закрывает кадр-глитч
  при входе на `/home` уже на дне (back-navigation / восстановленный скролл).
- **README:** к v1-секциям (§5/§6.1/§7/§8) добавлены **§3** (файла `derive.ts`,
  убрать `isManualMobileState`) и **§6** (таблица контекста, +`manualOverride`).
- **Required-поле `MachineContext.manualOverride`** ломает ровно 4 места сборки
  (`engine.ts` init + 3 `makeContext`); остальное ловит `tsc`. `LayoutProvider`
  безопасен (`Partial`).

## 1. Анализ текущего состояния

### Проблема

- `ToggleButton` рендерится по `hasToggle = hasToggleFor(bp)` = `bp !== 'desktop'`
  (`layoutSnapshot.ts:94`, `derive.ts:8-10`) — статический предикат по брейкпоинту,
  не знающий ни про `/home`, ни про источник текущего `mode`.
- На мобильном `/home` кнопка отображается уже на старте (scrollY=0, mode=`fullscreen`),
  хотя навбар там управляется scrub-твином (`useNavPosition.ts:39-55`).

### Root cause

Авто-верх `/home` (fullscreen, источник route/scroll) и ручное открытие
(fullscreen, источник toggle) **неразличимы по `mode`** — нужен источник.
Текущий дискриминатор `isManualMobileState(bp, lastSource, mode)` опирается на
`lastSource`, но движок перезаписывает его на `'scroll'` при каждом граничном
событии (`engine.ts:122-129`), даже когда `REACH_BOTTOM` сохранил ручной mode
(`transition.ts:120-124`). Итог — «corner»: после доката к дну спейсера ручное
состояние переживает mode, но теряется признак ручного управления.

### Требуемое поведение (зафиксировано с заказчиком)

| Сценарий (/home)                                | progress | mode / источник                 | Кнопка             |
| ----------------------------------------------- | -------- | ------------------------------- | ------------------ |
| Старт / верх (авто)                             | 0        | fullscreen / route              | скрыта             |
| Скролл вниз по спейсеру (авто)                  | (0,1)    | последняя граница               | скрыта             |
| Дно / контент — спейсер пройден (авто)          | 1        | invisible моб. / standard табл. | **видна**          |
| Обратный скролл, навбар открыт вручную (mobile) | (0,1)    | fullscreen / toggle             | **видна**          |
| Дошли до верха → `REACH_TOP`                    | 0        | fullscreen / scroll             | скрыта             |
| Tablet в scrub-полосе                           | [0,1)    | —                               | скрыта             |
| Вне `/home`                                     | —        | любой                           | видна (как сейчас) |

## 2. Целевая архитектура

```text
transition(state, event, ctx)
  │  REACH_BOTTOM: сохраняет state и manualOverride, если ctx.manualOverride
  ▼
engine.send() → context.manualOverride (+ lastSource, как раньше)
  ▼
resolveLayout() → snapshot.isManualToggle = bp==='mobile' && ctx.manualOverride
  ▼
NavigationBar → ToggleButton props: isHome / isManualToggle
  ▼
useToggleVisibility(ref, { isHome, isManualToggle })
  │  не-home: снять класс isHidden
  │  home: bus.on('scroll:progress') →
  │        hidden = !(progress >= 1−eps || isManualToggle)
  ▼
ToggleButton.module.css .isHidden { visibility:hidden; pointer-events:none }
```

Поток **машина→снапшот→рендер** не меняет природу (README §2): по-прежнему
`transition → snapshot → CSS`. Новое — слой **императивной видимости кнопки**
через gsapBus, потому что середина скролла машиной не выражается
(mode не меняется mid-scroll).

- [ ] **Новый** `nav/ToggleButton/useToggleVisibility.ts` (с `lastProgressRef`, D16):

```ts
export function useToggleVisibility(
  btnRef: RefObject<HTMLButtonElement | null>,
  opts: { isHome: boolean; isManualToggle: boolean },
) {
  const bus = useGsapBus();
  const lastProgressRef = useRef(0);
  useEffect(() => {
    const el = btnRef.current;
    if (!el) return;
    if (!opts.isHome) {
      el.classList.remove(styles.isHidden);
      return;
    }
    const apply = () =>
      el.classList.toggle(
        styles.isHidden,
        !(lastProgressRef.current >= 1 - EDGE_EPS || opts.isManualToggle),
      );
    apply();
    return bus.on('scroll:progress', ({ progress }) => {
      lastProgressRef.current = progress;
      apply();
    });
  }, [bus, btnRef, opts.isHome, opts.isManualToggle]);
}
```

Стартовый `apply()` использует `lastProgressRef.current` (=0 на монтировании,
либо последний известный прогресс при перезапуске эффекта — закрывает глитч
при входе на `/home` уже на дне).

## 6. Риски и принятые решения

- **Corner «повторный докат к дну»** — закрывается D1/D3 (флаг переживает `REACH_BOTTOM`).
- **Тест-харнес** — H3 (D14) ассертит реальное состояние машины (resolved-final),
  а не кодировку результата; `undefined` на `TransitionResult` — протокол «не трогать»,
  он никогда не является значением машины (`MachineContext.manualOverride: boolean`).
  Ключевой функциональный разрыв `undefined` vs `false` существует только при
  `ctx.manualOverride === true` (preserve vs reset) — покрыт кейсом INTRO_COMPLETE.
- **Начальный кадр** — убирается стартовым классом из рендера (D5/D8), реакция на
  scroll — мгновенная подписка `scroll:progress`; `lastProgressRef` (D16) страхует
  перезапуск эффекта mid-скролла.
- **Intro** — осознанно вне скоупа (D10).
- **`isManualToggle` назван по смыслу**, а не «showToggle», т.к. отражает _ручное
  состояние_, а не финальную видимость (final видимость = прогресс-правило).
