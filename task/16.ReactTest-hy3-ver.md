# Задача 16 — ReactTest (hy3): фиксация GSAP-логики навбара тестами

Навбар «накручивается»: в `useNavPosition.ts`, `useToggleVisibility.ts` и
`GsapProvider.tsx` растёт оркестрация GSAP — решения «кто владеет позицией»,
условия skip, сохранение прогресса при пересборке твина, boundary-detection
спейсера, guard-ы `SCROLL_TO_END`. Чистый слой (машина + движок) уже покрыт
(задача 13), а эти **политики решений и перерасчёты** — нет: они вшиты в
React-хуки/провайдер и не проверяются ни одним тестом.

**Цель (подход Hybrid):** вынести политики в чистые функции + зафиксировать их
юнит-тестами в `node`-окружении, плюс **один** jsdom-тест на самую хрупкую
GSAP-оркестрацию (rebuild scrub-твина без сброса `x` в 0) через **лёгкий
harness** (без полного mount `NavigationBar`).

> Отличие от `16.ReactTest-deepseek-ver.md` / `16.ReactTest-minimax-ver.md`:
> здесь не «только чистые функции» и не happy-dom. Выбрано: **jsdom** (надёжнее
> для GSAP-CSSOM), **Hybrid** (1 jsdom-тест), расширение существующего
> `machine/geometry.ts` (а не новый `navPolicy.ts`), **лёгкий harness**
> (`rebuildScrubTween` тестируется напрямую, без провайдеров).

## 0. Контекст и предпосылки

- **Покрыто (task 13):** `machine/` (`transition`, `derive`, `geometry`,
  `layoutSnapshot`) + не-React `engine.ts`. Окружение `vitest` → `node`,
  никакого DOM. Запуск `npm run test`, гоняется в pre-commit.
- **Не покрыто:** вся React-территория (`gsap/`, `context/`, `slots/`, `nav/`)
  — и именно там сейчас копится сложная логика.
- **Текущий `vitest.config.ts`:** `environment: 'node'`,
  `include: ['src/**/*.test.ts']`. Значит: DOM-тест кладём как `*.test.ts` с
  шапкой `// @vitest-environment jsdom` (попадает в glob без правки конфига),
  а чистый сьют остаётся на `node` и не платит цену jsdom в pre-commit.
- **GSAP в тест-DOM:** ядро (`gsap.to/fromTo` по инлайн-стилям, `x`, `transform`)
  работает в jsdom — GSAP просто пишет `el.style`. `tween.progress(p)`
  **синхронен**, RAF не нужен для ассертoв. `getComputedStyle` надёжнее в jsdom,
  чем в happy-dom (поэтому jsdom, а не happy-dom). ScrollTrigger/реальный скролл
  в обоих сломаны — но наш jsdom-тест едет на **paused plain-твине** через
  ручной `progress()`, ScrollTrigger не задействован.

## 1. Анализ текущего состояния

### Инвентарь непокрытой логики (весь навбар)

| #   | Кусок логики                                                         | Где живёт                      | Что решает / считает                                                                                                                      |
| --- | -------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| P1  | **buildScrub** — строить ли scrub-твин, `endX`, сохранение прогресса | `useNavPosition.ts:43-78`      | `!isHome` → килять твин; `isHome` → `endX = getNavTransform(homeEndState, innerWidth).navX`, прогресс старого твина переживает пересборку |
| P2  | **Discrete skip** — владение `x` на `/home`                          | `useNavPosition.ts:82-112`     | `isHome && !manualNow && !prevManual` → пропустить `gsap.to` (scrub владеет x)                                                            |
| P3  | **Resync guard** — пересинхрон с спейсером + подписка на bus         | `useNavPosition.ts:132-142`    | `!isHome \|\| isManualToggle` → не пересинхронизировать и не подписываться                                                                |
| P4  | **Видимость toggle**                                                 | `useToggleVisibility.ts:46-51` | `hidden = !(progress >= 1 - EDGE_EPS \|\| isManualToggle)`                                                                                |
| P5  | **Boundary detection** спейсера (top/mid/bottom)                     | `GsapProvider.tsx:70,84-96`    | `progress <= EDGE_EPS` → top; `>= 1 - EDGE_EPS` → bottom; иначе mid; fire только на смене границы                                         |
| P6  | **SCROLL_TO_END guard**                                              | `GsapProvider.tsx:37-49`       | не перематывать, если уже в конце (`progress >= 1 - EDGE_EPS`) или `st.end` не число                                                      |

### Почему это надо фиксировать

1. Правки в «кто владеет x» и skip-условиях ломают поведение **без единого
   красного теста** — регрессии уезжают в прод.
2. `endX` связывает `homeEndState` (машина) и `window.innerWidth` (браузер) —
   перерасчёт легко сломать при рефакторинге машины.
3. `buildScrub` пересобирает твин **с сохранением прогресса** — тонкая логика,
   уже порождавшая кадровые глитчи (комментарий `useNavPosition.ts:45-48`:
   навбар «прыгал» в fullscreen перед анимацией). Это единственная часть,
   требующая реального GSAP → ловим jsdom-тестом (Фаза 3).
4. `boundary`-память (`lastBoundary`) и guard-ы `SCROLL_TO_END` — классические
   перерасчёты, где off-by-one на `EDGE_EPS` легко пропустить.

### Принцип разделения

Всё, что является **решением или вычислением** — выносится в чистые функции
(§3). В хуках/провайдере остаётся только **обвязка** (refs, `useGSAP`,
подписки, вызовы `gsap.fromTo`/`gsap.to`). Это ровно паттерн движка
(`engine.ts` — тонкий оркестратор над чистой `transition`).

## 3. Извлекаемые функции (детально)

### 3.1 Чистые функции — `machine/geometry.ts`

```ts
// EDGE_EPS — перенос из GsapProvider.tsx:10
export const EDGE_EPS = 0.0001;
```

**F1. `computeToggleHidden`** (P4, `useToggleVisibility.ts:49`)

```ts
export function computeToggleHidden(opts: {
  progress: number;
  isManualToggle: boolean;
  edgeEps?: number; // default EDGE_EPS
}): boolean;
```

Семантика: `!(progress >= 1 - edgeEps || isManualToggle)`. Граница `>=`
включительная: на дне (`progress = 1`) и на краю `1 - eps` кнопка видна.

**F2. `resolveSpacerBoundary`** (P5, `GsapProvider.tsx:84-96`)

```ts
export type SpacerBoundary = 'top' | 'mid' | 'bottom';
export function resolveSpacerBoundary(
  progress: number,
  edgeEps?: number,
): SpacerBoundary;
```

Семантика: `<= edgeEps` → `'top'`; `>= 1 - edgeEps` → `'bottom'`; иначе `'mid'`.

**F3. `shouldFireBoundary`** (P5, guard «только на смене»)

```ts
export function shouldFireBoundary(
  prev: SpacerBoundary,
  next: SpacerBoundary,
): boolean;
```

Семантика: `prev !== next`.

**F4. `shouldScrollSpacerToEnd`** (P6, `GsapProvider.tsx:40-41`)

```ts
export function shouldScrollSpacerToEnd(opts: {
  progress: number;
  end: number | undefined;
  edgeEps?: number;
}): boolean;
```

Семантика: `typeof end === 'number' && progress < 1 - edgeEps` (не перематывать
с контента вниз, `end` вычислен).

**F5. `shouldBuildScrub`** (P1-часть, `useNavPosition.ts:49`)

```ts
export function shouldBuildScrub(isHome: boolean): boolean;
```

Семантика: `isHome` — вне `/home` scrub-твин не нужен (x держит discrete).

**F6. `resolveDiscreteApply`** (P2, `useNavPosition.ts:82-96`)

```ts
export function resolveDiscreteApply(opts: {
  isHome: boolean;
  manualNow: boolean;
  wasManual: boolean;
}): { applyDiscrete: boolean; wasManualNext: boolean };
```

Семантика точная копия гейта:

- `isHome && !manualNow && !wasManual` → `{ applyDiscrete: false, wasManualNext: wasManual }`
  (ранний return **до** апдейта `wasManual` — поэтому `wasManualNext = wasManual`);
- иначе → `{ applyDiscrete: true, wasManualNext: manualNow }`.

> `getNavTransform(mode, viewport).navX` уже есть в `geometry.ts` — P1-конечный
> `endX` считается им; новой функции не надо (хук вызывает
> `getNavTransform(homeEndState, viewport).navX`).

### 3.2 GSAP-зависимый хелпер — `nav/NavigationBar/scrubTween.ts`

```ts
import gsap from 'gsap';

/**
 * Пересборка scrub-твина с сохранением прогресса (P1).
 * Инкапсулирует capture prevProgress → kill prev → fromTo(paused,
 * immediateRender:false) → progress(prevProgress). Без этого вызова твин
 * рендерился бы в progress 0 → x:0 (fullscreen) и навбар «прыгал» перед
 * анимацией (useNavPosition.ts:45-48).
 */
export function rebuildScrubTween(
  nav: HTMLElement,
  prevTween: gsap.core.Tween | null,
  endX: number,
): gsap.core.Tween {
  const prevProgress = prevTween?.progress() ?? 0;
  prevTween?.kill();
  const tween = gsap.fromTo(
    nav,
    { x: 0 },
    { x: endX, ease: 'none', paused: true, immediateRender: false },
  );
  tween.progress(prevProgress);
  return tween;
}
```

`useNavPosition.buildScrub` вызывает `rebuildScrubTween(nav, scrubTweenRef.current, endX)`
внутри `contextSafe`. Снимок-зависимость `useNavPosition` не меняется.

## 7. Риски и митигация

- **R1 — Рефакторинг хуков меняет поведение.** Митигация: Фаза 0 (базлайн),
  behaviour-preserving, тесты политик; каждая фаза — `npm run test`.
- **R2 — Тавтологические тесты.** Митигация: GWT-таблицы с числами/сценариями,
  а не пересказ формул; jsdom-тест ассертит реальное значение `x`, а не
  «вызван ли метод».
- **R3 — GSAP-CSSOM в jsdom.** Митигация: jsdom выбран вместо happy-dom именно
  из-за надёжного `getComputedStyle`; тест едет на paused plain-твине + синхронном
  `progress()` (без ScrollTrigger/RAF). Если `getProperty(nav,'x')` в jsdom
  вернёт нечисловое — запасной ассерт через `nav.style.transform` (parse translateX).
- **R4 — `EDGE_EPS` дублируется.** Митигация: единый источник в `geometry.ts`;
