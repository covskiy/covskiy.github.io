# Задача 13 — Юнит-тесты layout state-machine (vitest)

Замена smoke-скрипта `scripts/verifyLayoutEngine.ts` настоящим тестовым
раннером. Покрытие ограничено чистым слоем: `machine/` + не-React `engine.ts`.
React-территория (gsap/, context/, slots/, nav/) не трогается.

## 1. Анализ текущего состояния

### Что есть сейчас:

| Файл                              | Статус                                                                 |
| --------------------------------- | ---------------------------------------------------------------------- |
| `scripts/verifyLayoutEngine.ts`   | Smoke-харнесс 13 кейсов; **не запускается** документированной командой |
| `src/components/Layout/machine/`  | Чистые функции: `transition`, `derive`, `geometry`, `layoutSnapshot`   |
| `src/components/Layout/engine.ts` | Не-React оркестратор: `send/subscribe/getSnapshot/...`                 |
| —                                 | Тест-инфраструктуры в репо нет (нет vitest/jest)                       |

### Проблемы verify-скрипта (почему заменяем):

1. **Сломанный запуск.** Документированное `node --experimental-strip-types`
   падает с `ERR_MODULE_NOT_FOUND` — в `engine.ts`/`machine/*.ts` бес-extension
   импорты (bundler-стиль). Работает только `npx tsx`.
2. **Осиротел:** не в `tsconfig` (tsconfig.node.json включает только
   `vite.config.ts`), нет npm-скрипта, не в lint-staged, не в CI.
3. **Дефекты:** мёртвый код (`lastEvents`, `expectSource`), дублирующий
   `bpDefaultEnd` (= `homeEndStateFor` из `derive.ts`), имена кейсов с опечатками
   (`— ноп`) и вводящий в заблуждение кейс «ROUTE_CHANGED → /home форсит
   fullscreen» при `isHome: false` и ожиданием `invisible`.

### Сценарии, которые надо сохранить (из verify):

- TOGGLE: mobile `/home` fullscreen→invisible (со `SCROLL_TO_END`), invisible→fullscreen; mobile `/other`
  invisible→fullscreen; desktop no-op; tablet standard↔slim (с персистенсом `preferred`).
- REACH_TOP → fullscreen всегда (в т.ч. после slim).
- REACH_BOTTOM → `homeEndState` по `preferred`; no-op на mobile-состоянии,
  «запиненном» toggle-ом (`isManualMobileState`).
- ROUTE_CHANGED / BREAKPOINT_CHANGED: validate preferred (tablet slim/standard), сброс
  preferred → default на mobile.
- INTRO_COMPLETE → no-op.

## 2. Целевая архитектура

```
vitest.config.ts                # environment: node, include: src/**/*.test.ts,
                                # coverage v8 по src/components/Layout/**
src/components/Layout/
├── machine/
│   ├── transition.test.ts      # 13+ кейсы на чистом transition(): state/actions/preferredAfter
│   ├── derive.test.ts          # чистые хелперы derive.ts
│   ├── geometry.test.ts        # getNavTransform, deriveMainOffset
│   └── layoutSnapshot.test.ts  # resolveLayout → vars/pointerEvents/hasToggle/isSlim
└── engine.test.ts              # движок: send/subscribe/notify, getSnapshot/getMode,
                                # setViewport/setIsHome/dispose/registerSlot,
                                # квирк «notify при смене только source»
```

Запуск: pre-commit → `.husky/pre-commit` = `npx lint-staged` + `npm run test`.
Тайп-чек тестов отдельно не нужен — они в `src/`, их валидирует `tsc -b`.
