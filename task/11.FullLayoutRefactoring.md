# Задача 11 — FullLayoutRefactoring: новый layout-механизм (с нуля)

Большой план на всю модификацию. Замена текущего движка `src/components/layout/`
новым модулем `src/components/Layout/`, построенным с нуля. Направление
разработки — `task/chat-React Layout.txt` (контекстная state machine →
`LayoutSnapshot` → GSAP анимирует CSS-переменные → CSS задаёт размеры/позиции
слотов). Решения зафиксированы в этой сессии; реализация идёт по частям в
отдельных сессиях.

## 1. Целевая архитектура

Поток данных (из `chat-React Layout.txt`):

```text
GSAP 60fps events
  → GsapLayoutBridge (детектит редкие точки, edge-triggered)
  → LayoutEngine / LayoutProvider (state machine + LayoutSnapshot)
  → useLayoutApplier (анимирует CSS-переменные на корне через GSAP)
  → layout.css (превращает vars в размеры/позиции слотов)
```

Роли:

| Сущность                 | Ответственность                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| `GsapProvider`           | GSAP-инфраструктура: bus, ticker, cleanup. **Не знает про layout.**                            |
| `GsapLayoutBridge`       | Адаптер: слушает 60fps-шину, edge-detection/throttle/hysteresis, шлёт редкие события в engine. |
| `LayoutEngine` (чистый)  | Reducer + ctx → `LayoutSnapshot`; `subscribe`/`send`/`getSnapshot`/`dispose`.                  |
| `LayoutProvider` (React) | Владеет engine + snapshot, разметка, контексты, `useLayoutApplier`.                            |
| CSS                      | Превращает `--vars` в геометрию слотов.                                                        |

## Часть I — чистое ядро (state machine) + движок + GSAP-шина

Модули создаются без связей со старым кодом. `machine/` — чистый слой (без React/DOM).

### I.1. `src/components/Layout/machine/`

```
machine/
├── layoutMode.ts     # LayoutMode, LayoutEvent, LayoutChangeSource, MachineContext
├── transition.ts      # transition(state, event, ctx) → TransitionResult
├── derive.ts          # getDefaultState, homeEndStateFor, isManualMobileState,
│                      #   isPreferredStateValid, hasToggleFor, isHomePath
├── geometry.ts        # SLIM_WIDTH, getNavTransform, deriveMainOffset → vars
└── layoutSnapshot.ts  # LayoutSnapshot, LayoutVars, LayoutTransitionOptions
```

Ключевые типы:

```ts
export type LayoutMode = 'fullscreen' | 'standard' | 'slim' | 'invisible';
export type LayoutChangeSource = 'toggle' | 'route' | 'breakpoint' | 'scroll';
export type Breakpoint = 'mobile' | 'tablet' | 'desktop'; // из src/utils/breakpoints

export type LayoutEvent =
  | { type: 'TOGGLE' }
  | { type: 'REACH_TOP' }
  | { type: 'REACH_BOTTOM' }
  | { type: 'ROUTE_CHANGED' }
  | { type: 'BREAKPOINT_CHANGED'; bp: Breakpoint }
  | { type: 'INTRO_COMPLETE' }; // reserved, noop

export interface MachineContext {
  bp: Breakpoint;
  isHome: boolean;
  preferred: LayoutMode | null; // ручной tablet-выбор slim/standard
  lastSource: LayoutChangeSource;
  source: LayoutChangeSource; // source текущего события (маппинг event.type)
}
```

`transition` — чистая reducer-функция, перенос семантики из старого
`machine/transition.ts` (те же guard'ы): desktop `TOGGLE` → noop; mobile
`invisible ↔ fullscreen` (+ `SCROLL_TO_END` на `/home` при сворачивании);
tablet `standard ↔ slim` + `preferredAfter`; `REACH_TOP` → fullscreen
(автоскролл > ручной); `REACH_BOTTOM` зависит от
`isManualMobileState`/`preferred`; `ROUTE_CHANGED`/`BREAKPOINT_CHANGED` —
home → fullscreen, иначе дефолт bp.

**`LayoutSnapshot` и vars (без `data-*`)**

```ts
export type LayoutVars = Partial<Record<string, string | number>>;

export interface LayoutSnapshot {
  value: LayoutMode;
  context: MachineContext;
  vars: LayoutVars; // CSS-переменные на корне — единственный канал сигналов
  scrollLocked: boolean; // зарезервировано (modal/immersive в будущем)
  transition: LayoutTransition;
}
```

`geometry.ts` считает vars (вертикальная панель, как в текущем движке —
`getNavTransform` / `deriveMainOffset`), например:

```
--nav-x:                0 | -100vw | calc(-100vw + 80px)* — окно .nav
--nav-pointer-events:    none | auto
--nav-content-offset:    25vw | 80px | 0                (margin-left <main>)
--layout-state:          fullscreen | standard | slim | invisible   (параметры, для отладки)
```

Логика «bp + isHome + preferred → `--nav-content-offset`» остаётся прежней
(`mobile → 0`; home + fullscreen → `homeEnd`; иначе `standard → 25vw`,
`slim → 80px`).

Примечание: в вертикальной модели измерение высоты навбара (ResizeObserver из
исследования) **не нужно** — отступы не зависят от высоты.

### I.2. `src/components/Layout/engine.ts`

Внешний (не-React) движок. Реализация по образцу `createLayoutEngine` из
`task/chat-React Layout.txt`, но под нашу машину:

```ts
export interface LayoutEngine {
  send: (event: LayoutEvent) => void;
  subscribe: (fn: (snapshot: LayoutSnapshot) => void) => () => void;
  getSnapshot: () => LayoutSnapshot;
  dispose: () => void;
}
export function createLayoutEngine(
  initial?: Partial<MachineContext>,
): LayoutEngine;
```

Внутри:

- текущий `context` (`bp`, `isHome`, `preferred`, `lastSource`) и текущий `mode`;
- `send`: картирует `event.type → source`, вызывает чистый `transition`;
  при реальном переходе строит новый `LayoutSnapshot` (vars + transition options)
  и уведомляет listeners;
- transition options: для дискретных событий — `{ duration: 0.45, ease: 'power3.inOut' }`;
  первый snapshot (инициализация) — `{ duration: 0 }`;
- `SLOT_MEASURED` в этой модели отсутствует (см. I.1).

### I.3. `src/components/Layout/gsap/`

```
gsap/
├── gsapBus.ts            # типизированная 60fps-шина на gsap.ticker
├── GsapProvider.tsx      # инфраструктура: bus + ticker + cleanup; layout-agnostic
└── GsapLayoutBridge.tsx  # (см. Часть II)
```

`gsapBus.ts` — минимальный emitter:

```ts
type GsapChannel = 'scroll:frame' | 'frame';
type ScrollFrame = { y: number; delta: number; time: number };
interface GsapBus {
  on: (channel: GsapChannel, fn: (payload: ScrollFrame) => void) => () => void;
  emit: (channel: GsapChannel, payload: ScrollFrame) => void;
  dispose: () => void;
}
export function createGsapBus(): GsapBus; // gsap.ticker.add → emit 'scroll:frame'
```

`GsapProvider` отдаёт через контекст `useGsapBus()`. Никакой логики про navbar.

## Часть II — React-обвязка, мост, слоты, CSS, UI, интеграция, удаление

### II.1. `context/`

```
context/
├── layoutContexts.ts   # EngineContext + SnapshotContext + хуки
└── LayoutProvider.tsx
```

Public API (новый контракт):

```ts
useLayoutEngine(): LayoutEngine;
useLayoutSnapshot(): LayoutSnapshot;
useLayoutSend(): (event: LayoutEvent) => void;
useLayout(): {
  mode, snapshot, send, toggle,
  registerScrollTrigger, onScrollProgress, onToggleVisibility, getHomeEndState,
};
```

- `LayoutProvider`: `useRef(createLayoutEngine)` + `useState(snapshot)`,
  подписка через `engine.subscribe(setSnapshot)`;
- реакция на `useBreakpoint()` → `send({ type: 'BREAKPOINT_CHANGED', bp })`,
  на `useLocation()` → `send({ type: 'ROUTE_CHANGED' })`;
- держит корневой ref (для `useLayoutApplier`) и реестр слотов.

### 2.2. `GsapLayoutBridge.tsx`

Компонент-эффект (рендерит `null`), внутри обоих контекстов. Перевод количества
60fps-кадров в редкие события машины: edge-detection по границам спейсера
(`REACH_TOP` / `REACH_BOTTOM`), throttle ~72px на «намерение» скролла
(SCROLL_UP/DOWN — будущий авто-hide). Доступ к движку — только через
`useLayoutSend()` (не знает внутренностей).

### 2.3. `slots/`

```
slots/
├── LayoutRoot.tsx        # корневая нода: здесь живут CSS-переменные; ref для applier'а
├── LayoutSlot.tsx        # слот (navbar / content): позиционируется через vars
├── useLayoutApplier.ts   # snapshot → CSS-переменные на корне + scrollLock
└── hooks.ts              # registerSlot / registerMeasureElement (callback-рефы)
```

- `useLayoutApplier(rootRef)`: подписка на `engine.subscribe`; `gsap.to(root,
vars, { duration, ease })` + dataЧ никогда не твинит по кадру layout-height;
  `scrollLocked → document.documentElement.style.overflow = 'hidden'`;
  после дискретных переходов — `ScrollTrigger.refresh()` (не в `onUpdate`, см.
  файл исходного исследования).
- `LayoutSlot(id, children, className)`: outer `[data-layout-slot=id]` + inner
  `[data-layout-slot-inner=id]` (для будущего измерения; в vertical-модели не
  обязательно).

### 2.4. `styles/layout.css`

Строится на vars, без `data-*`:

```css
.layout-navbar {
  position: fixed;
  inset-block: 0;
  left: 0;
  z-index: 50;
  transform: translateX(var(--nav-x-toggle, 0));
  pointer-events: var(--nav-pointer-events, auto);
}
.layout-navbar-inner {
  width: var(--nav-inner-width, 80px);
}
.layout-main {
  margin-left: var(--nav-content-offset, 0);
  width: calc(100% - var(--nav-content-offset, 0));
}
```

Корень root предопределяет переменные; значения приходят из `LayoutSnapshot.vars`
через `useLayoutApplier`.

### 2.5. `nav/` (презентационный)

`VerticalNavigationBar.tsx` + `ToggleButton` — читают `useLayoutSnapshot()`/`send`,
строят свои `useGSAP` (per-component animator). Позиция `.nav` — через applier на
корне (root vars). Scrub `/home` — через канал прогресса (60fps, без setState).

## 4. Не регресс (критерии поведения)

- Вертикальная панель: окно `100vw`, видимость через `translateX`, `margin-left`
  у контента.
- `/home` scrub fullscreen→homeEnd (канал прогресса; 60fps без setState).
- Mobile: `invisible ↔ fullscreen` (toggle), ручной pin «держится» до верха.
- Mobile `/home`: toggle → автопрокрутка к концу спейсера; `REACH_TOP` → fullscreen.
- Tablet: персистентный `preferred` slim/standard; `retargetScrub` при смене.
- Desktop: кнопки нет; `/home` fullscreen↔standard.
- Приоритет: автоскролл > ручной toggle; single-owner `.nav`.
- Смена роута/breakpoint: без «моргания» границы (offset не дёргается на каждом роуте).
