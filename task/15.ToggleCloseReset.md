# Задача 15 — ToggleCloseReset: сброс `manualOverride` при ручном закрытии навбара (mobile `/home`)

Закрывает follow-up дефект после внедрения «подтяжки контента» (пайплайн
`SCROLL_TO_END`): toggle-кнопка остаётся видимой в scrub-зоне после ручного
закрытия навбара. Решение — на уровне машины: флаг `manualOverride` теперь
означает «навбар **открыт** вручную», а не «было ручное управление».

---

## 0. Предпосылки (пройденные итерации)

- Пайплайн `SCROLL_TO_END` реализован: машина декларирует action (mobile
  close-ветка `transition.ts`), движок публикует его через
  `engine.subscribeActions`, `GsapProvider` доскролливает страницу к концу
  спейсера (`gsap.to(window, { scrollTo: st.end })`) — контент подтягивается
  вместо пустого spacer-а.
- Известный отдельный дефект — навбар-панель не уезжает при дискретной
  анимации на `/home` (scrub остаётся владельцем позиции). **Вне скоупа**:
  фикс в следующих итерациях.
- Task-14 (`ToggleVisibilityHome`) зафиксировал протокол флага
  `manualOverride`: ручной override на mobile `/home`, видимость кнопки через
  `isManualToggle` + `useToggleVisibility`.

---

## 1. Анализ текущего состояния

### Проблема

После ручного закрытия навбара (`TOGGLE` fullscreen→invisible) на mobile
`/home` и программной подтяжки контента к верху (`progress → 1`,
`REACH_BOTTOM`) кнопка toggle остаётся видимой при обратном скролле: навбар
подтягивается через scrub (как и должен), но кнопка не прячется.

### Root cause

Протокол task-14 (D12: «`TOGGLE` mobile → `manualOverrideAfter: true`»
безусловно) не различает ручное **открытие** и ручное **закрытие**. Цепочка,
приводящая к багу:

```
TOGGLE fullscreen→invisible → manualOverrideAfter: true   (ручное закрытие!)
→ REACH_BOTTOM: preserve (ctx.manualOverride)              → флаг остаётся true
→ обратный скролл: progress ∈ (0,1)
  isManualToggle = bp==='mobile' && manualOverride == true
  useToggleVisibility: hidden = !(progress ≥ 1−eps || isManualToggle)
  → кнопка видна в авто-scrub-зоне (БАГ)
```

### Требуемое поведение (mobile `/home`)

| Сценарий                                           | progress | mode / источник     | Кнопка     |
| -------------------------------------------------- | -------- | ------------------- | ---------- |
| Старт / верх (авто)                                | 0        | fullscreen / route  | скрыта     |
| Скролл по спейсеру (авто)                          | (0,1)    | последняя граница   | скрыта     |
| Дно / контент                                      | 1        | invisible           | видна      |
| Ручное **открытие** → обратный скролл              | (0,1)    | fullscreen / toggle | видна      |
| Ручное **закрытие** → подтяжка контента            | 1        | invisible           | видна      |
| **Обратный скролл после ручного закрытия (новое)** | (0,1)    | invisible / scroll  | **скрыта** |
| Верх после закрытия (`REACH_TOP`)                  | 0        | fullscreen / scroll | скрыта     |
| Вне `/home`                                        | —        | любой               | видна      |

## 2. Фиксируемые решения

| #   | Решение                                                                                                                                                                                                                                                                 |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Семантика флага: `manualOverride` = «навбар **открыт** вручную и удерживается в этом состоянии».                                                                                                                                                                        |
| D2  | `TOGGLE` mobile close (`fullscreen→invisible`) → `manualOverrideAfter: false`; open (`invisible→fullscreen`) → `true` (контракт task-14 «обратный скролл при ручном открытии — кнопка видна» сохранён).                                                                 |
| D3  | `REACH_BOTTOM` preserve требует `ctx.manualOverride`; после close флаг `false` → else-ветка `homeEndStateFor`; на mobile `homeEndState = invisible` = текущий mode → state не меняется, actions `[]`. Case-9 «зафиксирован скрытым бургером» работает через else-ветку. |
| D4  | Формула `resolveLayout` / `isManualToggle` **не меняется** (`bp === 'mobile' && context.manualOverride`). Комбинация `invisible + manualOverride=true` становится недостижимой; добавление guard'а `value==='fullscreen'` — мёртвое дублирование, не вводим.            |
| D5  | **Tablet не затрагивается** — изменение изолировано в mobile-ветке `TOGGLE`; флаг на tablet не ставится и не читается (`isManualToggle` всегда `false`).                                                                                                                |
| D6  | Продолжаем тест-харнес H3 (resolved-final) и максимальную аннотацию `expectManualOverride` (конвенция task-14).                                                                                                                                                         |
| D7  | Осознанное отклонение от D12 task-14 («`TOGGLE` mobile → `true`» безусловно); новый протокол фиксируем в живых доках (README §5, testing.md глоссарий).                                                                                                                 |

## 3. План реализации (фазы)

### Фаза 0 — `machine/transition.ts`

Mobile close-ветка (state `fullscreen`):

```ts
// было:
manualOverrideAfter: true,
// станет:
manualOverrideAfter: false,
```

Open-ветка (`invisible`) и остальные ветки не трогаем.

### Фаза 1 — `machine/layoutMode.ts` (JSDoc)

- `TransitionResult.manualOverrideAfter` — протокол:
  `true` = ручное открытие (`TOGGLE` invisible→fullscreen) + `REACH_BOTTOM`
  (preserve); `false` = ручное закрытие (`TOGGLE` fullscreen→invisible) +
  reset-события (`REACH_TOP` / `ROUTE_CHANGED` / `BREAKPOINT_CHANGED` /
  `REACH_BOTTOM` без override); `undefined` = не трогать.
- Поле `MachineContext.manualOverride` — «ставится при ручном открытии
  навбара на mobile, снимается при ручном закрытии и reset-событиях».

### Фаза 2 — `machine/transition.test.ts`

- Кейс 1 (close, ~стр. 89): `expectManualOverride` → `false`.
- Кейс 2 (close→open, ~стр. 103/109): `false`, `true`.
- Кейс 9 (close→`REACH_BOTTOM`, ~стр. 216/222): `false`, `false` (state
  `invisible`, actions `[]` сохраняются).
- manualCases «когда на /home на mobile жмут бургер из fullscreen, флаг
  manualOverride становится true» → переименовать «...флаг manualOverride
  снимается (false)» + `expectManualOverride: false`.
- **Новый кейс:** manual open (`manualOverride: true`, `fullscreen`) →
  close`TOGGLE` (`invisible`, `false`) → `REACH_BOTTOM` (`invisible`, `false`,
  actions `[]`) — фиксация нового контракта «закрытый навбар не удерживается
  ручным флагом».
- Остальные кейсы (REACH_TOP / route / bp reset, INTRO_COMPLETE preserve,
  corner 2×`REACH_BOTTOM`, tablet) — без изменений.

### Фаза 3 — `engine.test.ts`

- Тест ~стр. 198–214: после close-TOGGLE `context.manualOverride` → `false`,
  `snapshot.isManualToggle` → `false`; переименовать (например, «когда на
  mobile /home жмут TOGGLE, навбар сворачивается и ручной флаг снимается»).
  Утверждения `snap.value === 'invisible'` и один вызов `fn` — без изменений.
- (Опц.) engine-зеркало нового кейса: close → `REACH_BOTTOM` → `invisible` +
  manual `false`.
- Corner 2×`REACH_BOTTOM` и true→true (стр. 233–253, 269–290) — без изменений
  (стартовый `initialContext.manualOverride: true`).

## 6. Риски и принятые решения

- **Новый UX:** после ручного закрытия кнопка больше не «держится» на
  обратном скролле в scrub-зоне. Зафиксировано с заказчиком (таблица §1.1);
  закрытая панель — авто-режим.
- **Отклонение от D12 task-14:** «`TOGGLE` mobile → `true`» безусловно. Новый
  протокол локальный (только mobile), покрыт машиной-тестами и зафиксирован
  в живых доках — дальнейшие правки опираются на него.
- **`resolveLayout` не меняется:** formula `isManualToggle` остаётся
  `bp==='mobile' && context.manualOverride`; достижимость гарантирует машина,
  а не составной guard.
- **Цена будущих правок снижается:** семантика флага однозначна («открыт
  вручную»), видимость кнопки больше не требует уточнения производного флага.
